# Кадастр — внутрішня карта ділянок ДЗК

Легкий вебзастосунок для невеликої команди. Працює насамперед на телефоні:
пошук за кадастровим номером, межі ділянки на супутнику, площа, «Поділитись»,
«Маршрут», збережені ділянки з нотатками. Дані ДЗК беруться з ЄДЕССБ від імені
однієї авторизованої сесії. Окремий процес `keepalive.py` не дає цій сесії
закінчитися.

```
Телефон ──HTTPS──► Caddy ──► app (FastAPI) ──cookies──► admin.e-construction.gov.ua
                                   ▲  │
                     data/edessb_cookies.json  ◄── keepalive.py (кожні ~4 хв)
                     data/edessb_status.json   ──► Telegram (якщо сесія впала)
```

* **app**: вебінтерфейс, реєстрація та вхід, проксі до ЄДЕССБ, кеш.
* **keepalive**: окремий процес. Регулярно звертається до ЄДЕССБ, зберігає
  оновлені сервером cookies і пише статус сесії. Нові cookies, завантажені в
  адмінці, підхоплює без перезапуску.
* Обидва процеси працюють з одним файлом cookies. Запис іде під блокуванням і
  через злиття, тож ротація cookies з будь-якого боку не губиться.

## Можливості

| | |
|---|---|
| Пошук | Маска `XXXXXXXXXX:XX:XXX:XXXX`. Вводите лише цифри (відкривається цифрова клавіатура), пошук стартує сам після 19-ї цифри. Є історія пошуків. |
| Ділянка | Контур на карті (зокрема MultiPolygon з отворами) і площа: офіційна, якщо API її віддає, або розрахована за геометрією. Також центр ділянки і всі поля, які повертає джерело. |
| Дії | Копіювати номер, поділитися посиланням (`/?cad=…`), маршрут у Google Maps, зберегти з нотаткою. |
| Карта | Підкладка «Супутник»/«Схема», «Моє місце», шар меж ДЗК і тап по карті (якщо налаштовані). |
| Доступ | Реєстрація із підтвердженням адміністратора (або за кодом запрошення, або закрита). Перший зареєстрований користувач стає адміністратором. |
| Адмінка | Статус сесії ЄДЕССБ, вставка нових cookies, перевірка «зараз», керування користувачами, журнал дій. |
| Офлайн-стійкість | Результати пошуку кешуються на 6 год, тайли на 72 год. Якщо сесія впала, показуються збережені дані з позначкою. |
| PWA | Можна «Додати на головний екран»: відкривається на весь екран, як застосунок. |

## 1. Розгортання на VPS (Docker, рекомендовано)

> Покрокова інструкція для DigitalOcean: **[docs/DEPLOY_DIGITALOCEAN.md](docs/DEPLOY_DIGITALOCEAN.md)**.

Потрібно: VPS з Ubuntu/Debian, домен з A-записом на IP сервера, відкриті
порти 80 і 443.

```bash
curl -fsSL https://get.docker.com | sh
```

```bash
sudo mkdir -p /opt/kadastr && sudo chown $USER /opt/kadastr
```

Скопіюйте вміст цієї папки в `/opt/kadastr` (через `scp`, `rsync` або git), потім:

```bash
cd /opt/kadastr && cp .env.example .env && cp config/upstream.example.toml config/upstream.toml
```

```bash
mkdir -p data && sudo chown 1000:1000 data
```

Відредагуйте `.env` (`DOMAIN`, `PUBLIC_URL`, за бажання Telegram) і
`config/upstream.toml` (див. розділ 3). Потім запустіть:

```bash
docker compose up -d --build
```

Відкрийте `https://ваш-домен`. Caddy сам отримає HTTPS-сертифікат.
**Одразу зареєструйтеся**: перший обліковий запис стає адміністратором.

Корисне:

```bash
docker compose logs -f keepalive
```

```bash
docker compose exec app python manage.py check
```

```bash
docker compose exec app python manage.py create-admin ivan "Іван Петренко"
```

Оновлення: замініть файли й виконайте `docker compose up -d --build`.

### Без Docker (systemd)

```bash
sudo useradd -r -m -d /opt/kadastr kadastr && cd /opt/kadastr
```

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
```

```bash
sudo cp deploy/systemd/*.service /etc/systemd/system/ && sudo systemctl daemon-reload
```

```bash
sudo systemctl enable --now kadastr-app kadastr-keepalive
```

HTTPS: встановіть Caddy (`apt install caddy`) і використайте `deploy/Caddyfile.systemd`.

## 2. Як дати застосунку сесію ЄДЕССБ (cookies)

### Що відомо про сесію ЄДЕССБ (перевірено на реальному сервері)

* Сесія — **одна cookie `session_edessb`** на хості `admin.e-construction.gov.ua`.
* Без запитів вона живе **1 годину**; кожен запит продовжує її ще на годину.
  Keepalive раз на ~4 хв тримає її з великим запасом.
* Мертва сесія → ЄДЕССБ відповідає `403` + HTML «час відповіді на запит закінчився».
* Cookie, взята з домашнього браузера, працювала із **закордонного** IP — жорсткої
  прив'язки до IP не помічено, і з-за кордону відповідали і ЄДЕССБ, і `data.gki.com.ua`.

### Кроки

1. Увійдіть в кабінет ЄДЕССБ (`admin.e-construction.gov.ua`).
2. F12 → вкладка **Application** (у Firefox — **Storage**) → **Cookies** →
   `https://admin.e-construction.gov.ua`.
3. Скопіюйте **Value** рядка `session_edessb` (виглядає як `s%3A…`).
4. У застосунку: Меню → Адміністрування → «Нові cookies» → вставте → **Зберегти
   і перевірити**. Має з'явитися «Сесія активна».
5. **Не натискайте «Вийти» в ЄДЕССБ** у тому браузері: це знищить сесію і на
   сервері. Просто закрийте вкладку.

Також приймаються весь рядок `Cookie: …` (Network → Request Headers), JSON з
розширення Cookie-Editor і формат `cookies.txt`. З консолі:
`python manage.py import-cookies файл`.

### Якщо щось не так з IP

* Якщо колись почнуться `403`/`503` саме з сервера (а з домашнього браузера все
  працює) — це геоблокування або прив'язка сесії до IP. Рішення: `proxy =
  "socks5://…"` з українським IP у `config/upstream.toml` (див.
  `docs/DEPLOY_DIGITALOCEAN.md`, розділ «Український проксі»), а cookie брати з
  браузера, що ходить через той самий проксі.

### Як працює keepalive

* Кожні `keepalive_interval ± keepalive_jitter` секунд (типово 240 ± 60) робить
  GET на `keepalive_urls` з cookies. Найкраще вказати **той самий API пошуку з
  реальним існуючим номером**: відповідь `"success": true` означає, що сесія
  жива.
* Сесія вважається мертвою, якщо API відповів редиректом (на id.gov.ua чи
  сторінку входу), повернув 401/403, віддав HTML замість JSON або
  `success != true`. За редиректом скрипт **не переходить**, тож на id.gov.ua
  нічого не шле.
* Нові `Set-Cookie` від сервера одразу зберігаються у спільний файл.
* Якщо сесія впала, приходить повідомлення в Telegram із посиланням на
  адмінку. Після вставки нових cookies скрипт перевіряє їх за кілька секунд.
  Коли сесія відновиться, прийде повідомлення «✅ відновлено».
* Ручна перевірка: `python keepalive.py --once` (код виходу 0 означає, що
  сесія жива).

> Сесію, яка закінчилась на сервері (абсолютний тайм-аут, вихід, зміна
> пароля), скрипт **не воскресить**: автоматичного входу через Дію чи КЕП
> немає й не повинно бути. Він лише не дає сесії вмерти від простою.

## 3. Налаштування джерела даних (`config/upstream.toml`)

Пошук налаштований на `dzk.api`: він віддає і геометрію, і атрибути ділянки.

```toml
search_url  = "https://admin.e-construction.gov.ua/api-user/dzk.api?cad_num={cadnum}"
result_path = "result"
```

У картці ділянки показуються: офіційна площа, цільове призначення, категорія
земель, форма власності, нормативна грошова оцінка й дата оцінки (порожні поля
приховуються). Площа за геометрією з'являється лише тоді, коли вона більш ніж на 5%
відрізняється від офіційної. Технічні поля `ppoint` і `zoom_to` приховано. Для
нестандартних назв полів є секції `[parcel.fields]`, `[parcel.labels]` і
`hidden_fields`.

Для keepalive лишається легший `dzk.api.coords` (лише геометрія).

**Шар меж ділянок** уже налаштований на публічний растровий шар:

```toml
tile_url = "https://data.gki.com.ua/api-user/rtile/parcels/ua/{z}/{x}/{y}.png"
tile_session = false
```

* Cookies ЄДЕССБ туди **не надсилаються**: потрібні лише заголовки «як з
  кабінету» (`Referer`, `Origin`, `sec-fetch-*`, секція `[layer.tile_headers]`).
  Тому межі на карті працюють, навіть коли сесія ЄДЕССБ впала. Помилки тайлів
  на статус сесії не впливають.
* Браузер ходить лише до вашого сервера. Тайли кешуються на диску (`tile_cache_hours`),
  порожні (404) теж, щоб не смикати джерело повторно. Нижче `min_zoom` запитів
  до джерела немає взагалі.
* **Джерело обмежує частоту запитів** (nginx за Cloudflare): на залп із десятків
  тайлів відповідає `503`/`403` і якийсь час «карає» IP. Тому застосунок шле не
  більше `tile_parallel` (3) запитів одночасно, повторює невдалі з паузою, після
  серії відмов робить паузу для всіх тайлів (`tile_breaker_*`), а браузер
  перезапитує тайл, що не прийшов, через 3, 8 і 20 с. Із часом кеш заповнюється, і
  карта відкривається миттєво.
* Якщо тайли не йдуть узагалі (у лозі `Джерело тайлів відмовляє … пауза`), спершу
  перевірте, чи вантажаться вони на карті ЄДЕССБ у вашому браузері. Якщо там
  працює, а з сервера ні, дайте застосунку cookies `data.gki.com.ua`: DevTools →
  Network → запит тайла до `data.gki.com.ua` → **Copy → Copy as cURL (bash)** →
  вставте в адмінці в «Нові cookies». З cURL беруться лише cookies цього домену,
  `session_edessb` не зачіпається.
* Параметри секції `[layer]` пишіть **до** рядка `[layer.tile_headers]`, інакше
  TOML віднесе їх до заголовків.

**Тап по карті** вмикається, коли знайдете в DevTools запит, який летить при
кліку на ділянку на карті ЄДЕССБ: `identify_url`, підстановки
`{lat} {lng} {x} {y} {zoom} {bbox}`.

Зміни в `upstream.toml` підхоплюються без перезапуску.

## 4. Безпека

* Паролі зберігаються як хеші scrypt. Вхід тримається у HttpOnly + Secure +
  SameSite cookie, сесії зберігаються на сервері й відкликаються при блокуванні
  чи зміні пароля.
* Обмеження спроб: 10 невдалих входів за 15 хв на логін і 30 на IP.
* CSRF-захист (кастомний заголовок + SameSite), CSP, HSTS. Документація API
  вимкнена.
* `data/edessb_cookies.json` створюється з правами `600`. **Це фактично ваш
  вхід в ЄДЕССБ**: не комітьте його й не передавайте нікому.
* Застосунок звертається до ЄДЕССБ від імені однієї облікової сесії.
  Переконайтеся, що таке використання узгоджене з правилами доступу у вашій
  організації. Тримайте `max_parallel` невеликим, щоб не створювати
  навантаження.

Бекап БД: `deploy/backup.sh` (у cron раз на добу).

## 5. Локальна перевірка без ЄДЕССБ

У `dev/mock_edessb.py` є імітація ЄДЕССБ: та сама форма відповіді, сесія
«вмирає» після 2 хв простою, cookies ротуються.

```bash
pip install -r requirements.txt && python dev/mock_edessb.py
```

Далі запустіть застосунок і keepalive з конфігом заглушки:

```bash
export COOKIE_SECURE=false UPSTREAM_CONFIG=dev/upstream.mock.toml NO_PROXY=127.0.0.1
```

```bash
uvicorn app.main:app --port 8000
```

```bash
python keepalive.py -v
```

Cookies для заглушки можна взяти з `curl http://127.0.0.1:9001/login`.

## Структура

```
app/main.py         маршрути, авторизація, адмін-API
app/upstream.py     клієнт ЄДЕССБ: пошук, тап, тайли, кеш
app/edessb.py       перевірка сесії, статус, Telegram (спільне з keepalive)
app/cookiestore.py  спільне сховище cookies (flock + злиття), імпорт форматів
app/normalize.py    розбір відповіді в «ділянку»
app/geo.py          проєкції, площа, тайли
keepalive.py        демон підтримки сесії
manage.py           службові команди
static/             інтерфейс (без збірки, Leaflet локально)
```
